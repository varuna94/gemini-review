# gemini-review

커밋 직전에 변경분을 **Claude 렌즈 서브에이전트 여러 개**가 관점을 나눠 리뷰하는 Claude Code 플러그인이다.
[1.11.0] **Gemini 가 쓸 수 있는지 확인하지 않고 곧바로 렌즈로 리뷰한다.** Gemini 3.x 교차 리뷰(Antigravity CLI)는
사용자가 직접 요청할 때만 쓰는 선택 기능이다.

같은 모델이 짠 코드를 같은 맥락에서 다시 읽으면 **같은 맹점을 공유한다.** 도입 당일
실측에서, "조용한 실패를 막겠다"며 넣은 가드가 두 번 연속 죽어 있었다. 렌즈 서브에이전트는 작성 의도를 모르는
새 맥락에서, 관점마다 끝까지 파고, 적대적 렌즈는 변경이 틀렸다고 가정하고 반례를 찾는다. 다만 Claude 끼리의
리뷰는 교차 리뷰(다른 모델)가 아니다 — 그래서 기록은 판정이 아니다(`_meta.passed` false).

1.10.x 까지는 Gemini 를 먼저 돌리고 수행되지 않을 때(exit 4)만 렌즈로 넘어갔다. Gemini 가 제대로 동작하지 않는
날이 이어져(쿼터 · 무응답 · 모델 목록 변동) 확인하는 데만 매번 몇 분에서 27분까지 썼고, 1.11.0 은 그 확인을 없앴다.

## 설치

```
/plugin marketplace add varuna94/gemini-review
/plugin install gemini-review@gemini-review
```

설치한 뒤 **Claude Code 세션을 새로 열어야** 스킬과 렌즈 서브에이전트가 잡힌다.

### 준비물

| 무엇 | 확인 | 없으면 |
|---|---|---|
| Python 3.7+ | `python3 --version` (Windows 는 `py --version`) | 대부분 이미 있다 |
| git | `git --version` | 리뷰 범위를 git 으로 정한다 |
| `agy` (Antigravity CLI) — **Gemini 교차 리뷰를 쓸 때만** | `agy --version` | [antigravity.google/cli](https://antigravity.google/cli) 에서 설치하고 Google 계정으로 인증한다 |
| Google AI Pro/Ultra 구독 — **Gemini 교차 리뷰를 쓸 때만** | — | agy 인증에 쓰인다. 무료 계정으로는 Gemini 리뷰가 돌지 않는다 |

렌즈 리뷰(기본)에는 `agy` 가 필요 없다. `agy` 는 **Google AI Pro/Ultra 구독**으로 인증되므로, 저장소가
`GEMINI_API_KEY`(무료 tier)를 따로 쓰고 있어도 그 quota 를 잠식하지 않는다.

파이썬 이름은 환경마다 다르다(우분투·맥 `python3`, Windows `py` · `python`). 스킬이
있는 쪽을 골라 실행하도록 안내한다. 못 찾으면 종료 코드 2 로 끝난다 — 리뷰를 돌리지 않은 채 "지적 없음"으로
지나가지 않는다.

## 쓰는 법

Claude Code 세션에서 `/gemini-review` 를 부르면 된다(커밋 직전이면 모델이 스스로 부른다). 스킬은 범위 인자에
`--lens` 를 붙여 **준비**하고, 준비 출력대로 렌즈 서브에이전트를 병렬로 띄운 뒤, 지적을 검증 · 반영하고
`--record-lens` 로 기록한다.

| 목적 | 인자 |
|---|---|
| 커밋 직전 (스테이징된 변경) — 기본 | `--staged --lens` |
| 경로 지정 커밋 직전 (`git commit -- 경로`) | `--paths 경로… --lens` |
| 마지막 커밋 | `--lens` |
| 최근 3개 커밋 | `--base HEAD~3 --lens` |
| 브랜치 전체 (PR 전) | `--base main --lens` |
| 렌즈 리뷰를 마친 뒤 기록 (커밋 게이트가 인정한다) | `--staged --record-lens --reviewer 이름 --summary 요약` |
| 범위 리뷰 결과를 보고한 뒤 준비 diff 지우기 [1.11.1] | `--base main --discard-lens` (준비와 같은 범위 인자) |
| Gemini 교차 리뷰 — 요청할 때만 | `--staged` 등 (`--lens` 없이) |
| Gemini 설치 · 로그인 점검 (코드를 보내지 않는다) | `--check` |

`--base` 는 **merge-base 기준(3-dot)** 이다. `--base main` 은 브랜치를 딴 지점
이후의 내 변경만 본다 — 그 사이 main 에 들어온 남의 커밋은 섞이지 않는다.
1.10.x 이름 `--prepare-fallback` · `--record-fallback` 도 `--lens` · `--record-lens` 와 같은 뜻으로 받는다.

### 렌즈

| 서브에이전트 | 언제 | 관점 |
|---|---|---|
| `gemini-review:lens-general` | 늘 | 일반 — 정확성 · 회귀 · 저장소의 반복 실패 계열 |
| `gemini-review:lens-adversarial` | 늘 | 적대적 — 변경이 내세우는 주장을 반례로 깨뜨린다 |
| `gemini-review:lens-wiring` | 늘 | 배선 — 새 값 · 가드 · 검사가 실제로 소비 · 실행되는가(silent-dead) |
| `gemini-review:lens-security` | 늘 | 보안 — 비밀 · 주입 · 신뢰 경계 · fail-open |
| `gemini-review:lens-tests` | 코드가 바뀌면 | [1.11.0] 테스트 — 변경을 되돌려도 초록인 테스트 · 실제 경로를 지나지 않는 검사 |
| `gemini-review:lens-compat` | 코드가 바뀌면 | [1.11.0] 호환성 — OS · 셸 · 런타임 판 · 인코딩 · 경로 · 줄바꿈 |
| `gemini-review:lens-state` | 코드가 바뀌면 | [1.11.0] 상태 · 자원 — 재실행 · 동시 실행 · 부분 실패 · 시간 경계 · 자원 누수 · 성능 절벽 |

렌즈는 플러그인에 든 읽기 전용 서브에이전트(`Read, Grep, Glob` 만)다 — 파일을 고치거나 명령을 실행할 수 없다.
**효율:** 준비가 변경 파일 이름으로 렌즈를 고른다. 문서(`.md` · `.rst` · `.adoc` · 확장자 없는 LICENSE 등)만 바뀌면
늘 도는 넷만 띄우고, 띄우지 않은 렌즈를 화면에 알린다. 모르는 확장자와 `.txt`(requirements.txt 등) · `.mdx` 는 코드로
친다(틀리면 렌즈가 하나 더 돌 뿐이다).

1. 범위 인자에 `--lens` — 리뷰 · 게이트와 같은 바이트의 diff 를 `<git 폴더>/gemini-review/` 에 0600 으로 쓰고,
   띄울 렌즈와 렌즈 프롬프트를 찍는다. Gemini(agy)를 부르지도 찾지도 않는다.
2. 렌즈를 한 메시지에서 병렬로 띄운다(작성 의도는 프롬프트에 넣지 않는다). 지적을 실측 검증해 반영한다.
3. 내용이 바뀌면 다시 준비해 렌즈를 다시 띄우고, 바뀌지 않았으면 `--record-lens` 로 기록한다. 준비한 diff 와
   sha256 이 다르면 기록하지 않는다. 같은 기록을 다시 돌리면 "이미 기록돼 있다"(exit 0)로 끝난다 [1.11.1].
   범위 리뷰(`--base`)는 기록하지 않고, 결과를 보고한 뒤 같은 범위 인자 + `--discard-lens` 로 준비 diff 를 지운다 [1.11.1].
   기록처럼 지운 준비보다 먼저 만든 준비(앞 회차 · 범위와 세션을 가리지 않는다)와 하루가 지난 준비도 함께 지우고, 그보다
   나중에 만든 준비는 개수와 폴더만 알린다.

같은 내용에 Gemini 가 지적(exit 5) · 텍스트 원문(exit 6) · 응답 뒤 내부 오류(`response_lost` exit 1, 1.11.1)를 낸 적이
있으면 렌즈 기록으로 덮을 수 없다 — 준비 · 기록이 거부된다. 민감 경로(`.env` · `*.pem` · `id_rsa` 등)가 diff 에 있으면 준비 · 기록이 exit 3 으로 멈추고 차단 목록을
찍는다 — 사용자가 목록을 보고 명시적으로 승인한 경우에만 `--allow-sensitive` 를 붙여 다시 준비 · 기록한다. ⚠ 준비는
exit 9(준비함 · 리뷰 아님)로 끝난다 — 렌즈를 띄우고 기록해야 끝난다. 연결 워크트리 · 서브모듈 · 저장소의 하위 폴더에서 연 세션에서는 준비 diff 가 작업 폴더 밖에
놓여, 권한 모드에 따라 렌즈의 Read 가 거부된다. 준비 출력에 `/add-dir <폴더>` 안내가 나오면 렌즈를 띄우기 전에
그 명령으로 폴더를 더한다 [1.10.1]. 자세한 절차는 스킬 문서(SKILL.md 「렌즈 리뷰 절차」)에 있다.

### Gemini 교차 리뷰 (선택)

사용자가 요청할 때만 `--lens` 없이 같은 범위 인자로 돌린다. 처음 쓰면 `/gemini-review --check` 를 먼저 돌린다.
agy · 로그인 · 모델 응답과 agy 출력 형식(JSON · 텍스트 출력의 모델 없음 안내 · `/quota` 쿼터 그룹 대응 포함)을
약 30초 안에 확인한다(0 정상 · 2 고칠 것이 있다 · 4 기다리면 풀린다). Gemini 리뷰가 수행되지 않으면(exit 4)
기다리거나 재시도하지 않고 곧바로 렌즈 리뷰로 간다 — 화면의 `렌즈 리뷰:` 줄이 다음 명령을 알려 준다.

그 밖의 인자(Gemini 전용): `--model`(기본 `gemini-3.1-pro-high` — **flash 로 낮추지 말 것**. agy 가 이 모델을
모를 때만 `agy models` 에서 고른 대체 주 모델(pro > flash 의 `-high`, 판이 높은 순)이 판정한다 —
`--model` 을 적으면 바꾸지 않는다. 모델 목록 변화는 `--check` 가 알려 준다),
`--timeout`(기본 `10m`), `--allow-empty`(빈 스테이징을 8 대신 0 으로), `--out`(결과 JSON 저장 경로. 생략하면
`~/.local/state/gemini-review/`, Windows 는 `%LOCALAPPDATA%\gemini-review\`),
`--ignore-quota-cache`(기록된 쿼터 차단을 무시하고 실제로 호출한다 — **사용자 전용**).
이 인자들은 `--lens` · `--record-lens` 와 함께 쓸 수 없다(exit 2) — 렌즈 리뷰가 그 모델로 리뷰했다고 읽히지 않게 한다.

두 리뷰에 같은 인자: `--allow-sensitive` — 민감 경로가 diff 에 있어도 진행한다. **사용자가 목록을 보고 명시적으로
승인했을 때만** 쓴다. Gemini 리뷰에서는 전송을, 렌즈 리뷰에서는 준비 · 기록을 허락한다.

⚠ `--out` 으로 저장소 안에 결과를 쓰면 **저장소 절대 경로**(`_meta.scope.repo`)와 리뷰 대상
코드가 그 파일에 담긴다. 그 경로를 gitignore 할 것.

## 결과를 읽는 법

⚠ **배너가 보이지 않으면 리뷰 · 준비는 수행되지 않은 것이다.** 종료 코드만 보고 판단하지 말 것. 렌즈 리뷰
준비는 `렌즈 리뷰 준비 v…` 배너, Gemini 리뷰는 아래 배너다.

```
범위: staged / 변경 파일 N개 / diff N자
```

| 종료 코드 | 뜻 |
|---|---|
| `0` | 통과 (주 모델의 `approve` · `approve_with_comments`). `--record-lens` 는 기록함 · 이미 기록돼 있음, `--discard-lens` 는 지움 · 지울 것 없음 — 판정이 아니다 |
| `1` | 파싱 실패 · 내부 오류. [1.11.1] Gemini 가 응답한 뒤 결과를 쓰기 전의 내부 오류는 `response_lost` 로 남는다(응답 앞부분 `response_excerpt` · 렌즈 기록으로 덮지 못한다) |
| `2` | 실행 실패 — git · `agy` 를 못 찾음, agy 가 실패를 알림(모델명 · 인증), `--out` · 렌즈 리뷰 기록에 못 씀, 렌즈 리뷰 준비 · 기록 거부, `--discard-lens` 실패 |
| `3` | 민감 경로가 diff 에 있어 중단(Gemini 전송 · 렌즈 준비 · 기록 모두) |
| `4` | **리뷰가 안 된 것이다** — 시간 초과 · 쿼터 소진 · 모델 무응답 · 빈 응답. '지적 없음'으로 읽지 말 것 |
| `5` | `request_changes` |
| `6` | 구조화 실패 (텍스트 모드로 리뷰는 받았다) |
| `8` | `--staged` · `--paths` 인데 커밋할 변경이 없다 — 리뷰가 안 된 것이다 |
| `9` | [1.11.0] `--lens` 준비함 — **리뷰가 아니다.** 렌즈를 띄워 리뷰를 마치고 `--record-lens` 로 기록해야 끝난다 |
| `130` · `143` | 중단(Ctrl+C · 종료 신호) — 리뷰가 안 된 것이다 |

**이 표에 없는 코드는 통과가 아니다.** exit 4 는 "Gemini 리뷰가 수행되지 않았다" 고 보고하고 화면의
`원인:` · `해결:` · `렌즈 리뷰:` 줄대로 한다 — 원인을 가리지 않고 곧바로 렌즈 리뷰로 간다 [1.11.0].

**Gemini 판정은 주 모델만 낸다.** 주 모델이 응답하지 않을 때 진단 모델(`--probe-model`)은 "주
모델만 죽었나, 도구가 죽었나" 를 가르는 데만 쓴다 — 그 모델로 리뷰를 받지 않는다.

결과 JSON(`--out`)의 `_meta.passed` 는 주 모델이 리뷰해 통과 판정을 냈을 때만 `true` 다.
`_meta.mode` 가 원인(`timeout` · `quota_exhausted` · `no_changes` …)을 말한다.

### exit 4 는 두 가지다 [1.5.0]

`_meta.quota_cached` 가 `true` 면 **이미 기록된 쿼터 차단** 때문에 리뷰를 요청하지 않고 끝난
것이다. 차단 기록이 있으면 `/quota` 로 아직 차단인지 확인하고(토큰 0), 대체 주 모델로 도는 동안에는 그 앞에
기본 모델 확인 · 모델 목록 조회도 한다 [1.10.2]. 즉시 다시 돌려도 같은 코드가 나온다 — Gemini 판정이 꼭 필요하면 화면에 적힌 재설정 시각 뒤에 돌리고, 아니면 곧바로
렌즈 리뷰로 간다.
그 값이 없으면 실제로 호출했다가 실패한 것이다(시간 초과 · 무응답 · 첫 쿼터 차단).

왜 이렇게 하는가: 쿼터에 걸린 agy 는 내부에서 8회까지 재시도한다. 실측에서 **609초를
태우고** exit 4 로 끝났고, 다음 실행이 같은 609초를 또 썼다. 차단이 한 번 기록되면 그 뒤
실행은 `agy -p "/quota"`(토큰 0 · 약 6초)로 먼저 확인하고, 아직 차단이면 리뷰를 요청하지
않는다. 풀린 것이 확인되면 기록을 지우고 정상 진행한다. **차단 기록이 없는 평상시에는
조회하지 않는다** — 추가 비용이 0초다.

### 1.5.0 이 더한 `_meta` 필드

| 필드 | 뜻 |
|---|---|
| `diff_sha256` | 리뷰에 **실제로 보낸 바이트**의 sha256. ⚠ `git diff \| sha256sum` 과는 다르다 — 스크립트가 디코딩·재인코딩한 UTF-8 이 대상이다 |
| `scope.repo` · `scope.branch` | 커밋 단위로 회차를 묶는 키. detached HEAD 면 `branch` 는 `null` |
| `written_at` | 결과를 쓴 시각(UTC). `in_progress` 기록에도 붙는다 |
| `calls[].usage` | 호출별 토큰(`input_tokens` · `output_tokens` · `thinking_tokens` · `cache_read_tokens` · `total_tokens`). 수치가 아닌 값은 걸러내고 그 키 이름을 `usage_dropped_keys` 에 남긴다 |
| `calls[].agy_turns` · `agy_duration_seconds` | agy 래퍼가 보고한 값. 기존 `seconds` 는 **스크립트가 잰 벽시계**로 별개다 |
| `calls[].usage_unavailable` | 텍스트 출력 호출에는 래퍼가 없어 토큰을 알 수 없다 |
| `quota_cached` · `quota_source` · `quota_cached_streak` | 쿼터 단락으로 끝났을 때. `quota_source` 는 `quota_query`(조회로 확인) 또는 `cached`(조회가 답하지 못해 기록으로 판단) |

시각 필드가 셋이라 헷갈리기 쉽다. `calls[].seconds` 는 스크립트가 잰 그 호출의 벽시계,
`calls[].agy_duration_seconds` 는 agy 가 보고한 값, `elapsed_seconds` 는 실행 전체다.

### 결과 폴더

결과는 실행마다 쌓이고 **90일이 지난 것은 결과를 쓸 때 지워진다** [1.10.2] — 결과에는 코드가 인용된 지적이
담긴다. 그보다 먼저 손으로 지워도 되지만, 이 폴더는 집계만이 아니라 **커밋 게이트가 통과 · 렌즈 기록을 찾고 렌즈 리뷰가
Gemini 지적 이력을 찾는 곳**이다 — 지우면 같은 내용을 다시 리뷰해야 커밋할 수 있고, 지운 지적은 렌즈 리뷰를 막지 않는다.
`--out` 으로 다른 곳에 쓴 결과도 이 폴더에 사본이 남는다 [1.10.1]. 쿼터 상태는 같은 폴더의
`quota-state.json` 이고(보존 기한 대상이 아니다), 지우면 다음 차단 때 다시 만들어진다.

**지적을 액면 그대로 받지 말 것.** 해당 코드와 데이터를 직접 보고 사실인지
확인한 뒤 고치고, 아니면 근거를 남기고 넘어간다. 리뷰어가 여럿이 됐다고 검증을
생략하면 오히려 위험하다.

## ⚠ Gemini 교차 리뷰는 diff 를 Google 서버로 전송한다

렌즈 리뷰(기본)는 diff 를 Google 로 보내지 않는다 — 그래도 민감 경로 가드는 렌즈 리뷰에도 걸린다(위 「렌즈」).
Gemini 교차 리뷰는 diff 를 Google 서버로 보낸다. 민감 경로(`.env` · `secrets/` · `*.pem` · `id_rsa` 등)가 diff 에 있으면 스킬이
**중단**한다. 다만 **그 가드는 diff 만 검사한다** — gitignore 된 `.env` 나 diff
안에 하드코딩된 키(`sk_live_…`)는 구조적으로 잡지 못한다.

사내 코드나 고객 데이터가 걸린 저장소에서는 **전송 자체가 허용되는지 먼저
판단**하라. `--mode plan` 고정이라 Gemini 가 파일을 수정하지는 못한다.

## 커밋 게이트 (선택) [1.6.0 · 1.7.0 · 1.11.0]

플러그인에는 Claude 의 `git commit` 을 막는 hook 이 들어 있다. **기본은 꺼져 있다.** 켜면
그 커밋이 담을 내용과 **같은 내용의 렌즈 리뷰 기록 또는 Gemini 통과 판정**이 결과 폴더에 있을 때만 Claude 의
커밋이 실행된다. 커밋 전 리뷰를 모델이 지시를 기억하는 데 맡기지 않게 된다. 막을 때 `해결:` 줄은 렌즈 리뷰
절차(`--lens` → 렌즈 → `--record-lens`)를 안내한다.

```
git config --global gemini-review.gate true           # 모든 저장소에서 켠다
git config gemini-review.gate false                   # 이 저장소만 끈다
git config gemini-review.gateFallback false           # 이 저장소에서 렌즈 리뷰 기록을 인정하지 않는다(Gemini 통과만)
```

- **판정:** 커밋이 담을 diff 를 모사해 sha256 을 재고, **같은 저장소**의 결과 가운데 `_meta.diff_sha256`
  이 같은 **가장 최근** 결과가 렌즈 리뷰 기록(`lens_reviewed`, 1.10.x 의 `fallback_reviewed` 포함) · exit 0 이거나
  Gemini 의 `reviewed` · `passed` · exit 0 이면 연다. 리뷰 뒤에 내용이 바뀌면 다시
  리뷰해야 한다. 같은 변경이라도 다른 저장소의 결과는 쓰지 않는다.
- **커밋 형태 [1.7.0]:** `git add … && git commit` · `-a` · `-i 경로` · `git commit -- 경로` 를 막지
  않고, 인덱스의 **임시 사본**에서 git 과 같은 규칙으로 담을 내용을 만든다(진짜 인덱스는 건드리지
  않는다). 실제로 커밋한 뒤의 diff 와 바이트까지 같음을 검사가 고정한다. 경로 지정 커밋은
  `--paths 경로…` 로 리뷰한다 — 두 세션이 작업 트리를 공유할 때 남의 스테이징을 건드리지 않는다.
- **렌즈 리뷰 기록 [1.7.0 · 1.10.0 · 1.11.0]:** `--lens` 로 준비한 렌즈 서브에이전트 리뷰를 마친 뒤
  `--record-lens --reviewer … --summary …` 로 기록하면 게이트가 인정한다. Gemini 시도는 필요 없다(1.10.x 는
  Gemini 가 exit 4 일 때만 기록했다). 같은 내용에 Gemini 가 응답(지적 · 텍스트 원문)을 낸 적이 있거나, 같은 내용으로
  준비한 diff 가 없으면 기록을 거부한다. 기록은 주 모델 판정이 아니다(`_meta.passed` false). 게이트는 준비
  시각(`_meta.prepared_at`)이 없는 옛 기록(1.9.0 이하)을 인정하지 않는다. 인정하지 않으려면 위의 `gateFallback false`
  — 그 저장소에서는 준비 · 기록도 거부되고 게이트는 Gemini 리뷰를 안내한다.
- **막는 꼴:** 모사하지 않는 인덱스 명령(`git reset` · `git rm` · `git stash` 등)을 커밋 앞에 이은 것,
  대화형 커밋(`--patch`), 저장소를 확정할 수 없는 명령(`cd $REPO` · `GIT_DIR` 등), 해석하지 못한
  명령, 파이썬을 못 찾은 경우, 게이트 내부 오류.
  Claude 가 게이트 설정(`gemini-review.*`)을 바꾸는 `git config` 명령도 막는다. 설정은 사람이 한다.
- 같은 내용의 판정 · 기록 뒤에 온 수행되지 않은 시도(쿼터 · 시간 초과 · 민감 경로 중단 등)는 그 판정 · 기록을 가리지
  않는다 [1.11.0]. 렌즈 기록은 **자기 신고**다 — 코드는 기록한 바이트가 준비한 바이트와 같은지만 확인한다.
- **막지 않는 것:** 스테이징이 빈 커밋(메시지만 고치는 `--amend`), `--dry-run`, Claude Code 밖의
  터미널에서 사람이 하는 커밋.
- **대상 저장소:** `cd` · `git -C` · `env -C` 처럼 경로가 적힌 명령은 그 저장소의 설정을 본다.
  `cd $REPO` 처럼 확정할 수 없으면 현재 폴더와 전역 설정 가운데 엄한 쪽을 본다. 그래서 **저장소에만
  켠 게이트**는 대상을 확정할 수 없는 명령을 막지 못한다 — 빠짐없이 막으려면 `--global` 로 켠다.
- `--out` 으로 다른 곳에 쓴 결과도 결과 폴더에 사본이 남아 게이트가 본다 [1.10.1].
- ⚠ **위협 모델은 망각이다.** 결과 파일 위조 · 설정 파일 직접 편집 · git alias 는 막지 않는다.
- ⚠ 리뷰를 돌리면 안 되는 저장소(전송이 허용되지 않는 코드 등)에서는 그 저장소만 끈다. 켜 둔
  채면 Claude 는 커밋하지 못하고 그 사실을 보고한다.
- 게이트는 git 만 실행한다. agy 를 부르지 않으므로 코드를 보내지 않는다.

## 저장소마다 리뷰를 날카롭게 하려면

저장소 루트에 **`.gemini-review.md`** 를 두면 렌즈 프롬프트에 그 파일이 맥락으로 들어가고(렌즈가 반복된 실패
계열을 가장 먼저 대입한다), Gemini 리뷰 지시에도 덧붙는다. 없어도 범용 렌즈로 동작한다.

적을 것은 그 저장소에서 **실제로 반복된 실패**다. 일반론이 아니라 사고 이력이다.

```markdown
이 저장소는 결제 정산 배치다. 금액 오류가 즉시 실손실이다.

## 실제로 반복된 실패
1. 통화 단위 혼재 — 원/센트가 세 지점에서 다르게 해석됨
2. 재시도 시 멱등성 깨짐 — 중복 정산 발생 이력
3. 집계 쿼리가 서로 다른 기간 필터를 씀
```

## 고칠 때

```
python3 tests/test_gemini_review.py   # 동작 검사 (수 초)
python3 tests/mutation_check.py       # 가드를 되돌리면 실제로 빨개지는지 (2분 안팎)
```

Windows 는 `python3` 대신 `py` 로 부른다.

가드나 문서의 규칙을 건드렸다면 두 번째도 돌린다. 테스트가 초록이라는 것만으로는
가드가 살아 있다는 증거가 아니다 — 이 저장소에서 두 번 그랬다.

## 업데이트

```
/plugin update gemini-review@gemini-review
```

마찬가지로 **세션을 새로 열어야** 새 판(스킬 · 렌즈 서브에이전트)이 로드된다. 렌즈 준비 배너 첫 줄(`렌즈 리뷰
준비 vX.Y.Z …`) · Gemini 리뷰 배너 첫 줄(`Gemini 교차 리뷰 vX.Y.Z …`)과 `스크립트:` 줄로 실제로 돈 판과 경로를
확인할 수 있다. 판 갱신 직후 세션에서 새 렌즈가 Agent 목록에 없으면 스킬이 `general-purpose` 대안을 안내한다. 판마다 달라진 점(특히 **1.4.0 의
종료 코드 · 결과 JSON 변경**)은 [CHANGELOG.md](CHANGELOG.md) 에 있다.
